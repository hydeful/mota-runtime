# 项目背景、学习体系与代码导览

## 游戏与研究目标

魔塔是确定性、单人、资源约束的序贯决策游戏。勇士的 HP、攻防、钥匙等决定哪些交互当前合法，以及交互后的资源状态。打怪、取物、开门的顺序会改变后续可达性和战损。不是实时动作游戏，也不是双人零和对抗；价值回传不能机械地逐层变号。

原任务是十层塔：从冻结起点开始，击败指定 skeleton captain，完成自动结算后立即终止。P48 起点为 MT3 (11,5,up)，HP 976、攻击 10、防御 10、钥匙黄/蓝/红=5/1/0。工程正确性由冻结状态、规则、动作模式和目标判定共同定义。

策略选择的是可达的对象交互，不是每次上下左右移动。底层历史拓扑仍含通行格节点，路径细节不应被误认为策略动作。P49 后来增加真正的对象图：21 个事件/对象节点，74 条关系边；运行时规则、合法集和搜索不返回格点寻路。地图坐标只在初始构建、参考认证及给人类回放时使用。

用户长期希望计算与网络直接使用拓扑信息，但本轮公开审查的主目标是**工程加速**。平面 CNN 和对象图实验是既有证据；不要求外部审查在此重新裁决输入表示的优劣。若提出表示压缩，必须说明是否改变模型函数、训练任务或算法行为。

## 当前选择：AlphaZero 式闭环

从随机网络开始，不注入最优路线、专家示范或穷举答案。网络输出策略先验 P 与状态价值 V；PUCT 搜索形成根访问分布，选取真实动作；完整 episode 的真实结果产生价值标签。经验池按位置抽样，SGD 更新后发布模型，后续采集实际消费新模型。评价数据不进入训练。

基本训练损失为策略目标交叉熵、价值误差和手动 L2。单人回报不交替变号，gamma=1。具体失败标签与成功 HP 归一化应以各冻结 config 为准，不把 P49 奖励配置无条件套到十层塔。

P45/P48 主要冻结规则：

|部分|实际约束/配置|
|网络|550×13×13 float32 输入；2 个残差块、32 通道；策略输出 713；价值头隐藏 256、tanh|
|搜索|PUCT，mean Q，cpuct=1.25，未访问 Q=0；每决策新增 100 次模拟；树复用必须区分继承访问和本次新增访问|
|探索|前 30 步的根噪声/采样按冻结 config；确定性评价另行关闭噪声|
|采集/更新|4 局 cohort；至少 512 新位置才触发更新；batch=64；新位置曝光系数 8，依原账本公式计算应做步数|
|回放|按位置均匀；容量 8192；不能偷换成按局均匀|
|优化|SGD lr=.01、momentum=.9、manual L2=.0001|
|缓存|绑定模型身份、schema 和完整观测；缓存原始 P/V，根噪声后加；不能跨模型误用缓存|
|发布|权重与状态身份可追溯；更新后被真实采集消费；完整训练债务需结清|

上述数字来自冻结 P45 配置和 P48 复盘；不是限制外部 AI 只能维持当前进程组织。修改采集屏障、模型滞后等会影响样本流，需作为行为变化方案单独验收。

## 实际调用链

`perf/control.py` 管理探测矩阵、预算、子进程及收尾；`perf/worker.py` 选择串行、并行或推理服务路径。P48 工程包装复用 `tasks/tower10/p45/runtime.py` 的 Runner 训练/经验/发布逻辑。

Runner 建环境与模型，采集时调用 Search；Search 选择边，调用环境的合法动作、状态转移、观测编码和模型推理，回传更新访问/Q。到终局后写 episode；训练路径读取/验证历史记录、构造样本、抽 batch、SGD、保存并发布新模型；下一轮采集消费该模型。

|代码路径（仓库根目录起）|阅读重点|
|`tasks/tower10/p45/runtime.py`|Runner、采集/回放/训练步账本、rng_state、atomic_torch、发布与恢复|
|`tasks/tower10/p45/search.py`|Node、Search、树复用、模拟预算、价值回传、P/V 缓存|

## P49 代码是如何接入的

小塔 9×5，31 通行格、21 个对象，初始 HP400；同源战斗和道具规则；所有完整合法路线都能通关，剩血 2～574。它验证简单顺序优化，不能用通关率衡量学习收益。奖励成功时 HP/900，900 来自初始400加全图500补给，不是用最优574归一化。

`p49/learning/` 是地图输入 CNN；`p49/topology/` 是对象关系网络；`p49/controlled/` 是后续受控 CNN A/B。它们的 runtime 通过读取并绑定原 P45 Runner 源码复用训练链，再做必要的接口适配。实际文件必须检查，不能因“复用 Runner”就认定所有配置和插桩完全一样。

|版本|网络输入/主体|规模与边界|
|地图 CNN|34×5×9，原 2×32 CNN|123994 总参数；713 策略槽，21 有效，其余永久屏蔽；其中约62972参数对应闲置输出|
|历史对象关系网络|节点21×27、关系2×21×21、勇士7；共享消息传递+均值价值池化|27586 参数，与地图 CNN 不等参；运行时无格点路径调用|
|受控 A/B|A 地图，B 完整对象拓扑序列化为1456数值并补74零，送入同34×5×9 CNN|两者123994参数、配对初始 state_dict 相同；B 的二维形状只是容器，不是平面地图；它也不是图网络，不具节点重排不变性|

P49 学习更新门槛降为64新位置，评价搜索显式使用100新增模拟。不要把 P49 与 P48 的 min_new_positions、输入体积或运行耗时混为同一工作负载。

## 数据与存储边界

真实状态包含资源、对象生命周期、任务标志；规则和图大多静态。原记录还带动作、mask、状态/观测身份、策略分布、模型身份和结算标签等审核信息。高频保存包括搜索/episode/训练/恢复状态；其目的与需要永久保存的最小信息量是两个问题。

允许审查者重设计日志、检查点、验证缓存和数据格式，但须说明崩溃后最多丢失多少工作、如何避免重复训练/提交、如何确保模型与样本身份一致。把 debug 审计搬到离线是候选方案，不应无条件删除规则或账本检查。
